# 同时使用 OpenClash

## 普通用户需要做什么？

先按 README 填写校园账号并启动插件。**不要为了使用 Portal Loginer，直接替换 OpenClash 的 DNS、订阅或规则。**

如果正常使用，不需要额外添加配置。如果只有代理开启时出现问题，先查看日志，并确认校园网本身是否可用。

## 为什么代理可能影响检测？

插件通过几个普通 HTTP 地址检查网络。透明代理可能接管这些请求，也可能接管域名解析。节点坏了时，请求失败并不一定代表校园账号掉线。

因此，插件会区分“发现校园认证页”和“请求没有成功”。遇到超时会保留现有登录，不会仅凭超时不断注销重登。

## 能否完全不受 OpenClash 影响？

1.4.0 尚未提供适用于不同固件和模式的通用实现。仅设置 HTTP 直连、绑定 WAN 网卡或写一条 DIRECT 规则，都不能保证同时绕过透明代理和 DNS。

此前使用的 UID、DSCP 标记和独立 DNS 配套，是一项特定环境的处理办法，依赖 OpenClash 版本、防火墙和 DNS 转发方式。它不应被描述成所有用户都需要配置的标准功能。

**没有安装 OpenClash 时，插件直接使用系统网络。现有版本不会自动更改 OpenClash 的设置。**

如果开启本机代理后一直显示“探测未确认”，这是当前版本需要排查的兼容问题。请提供相关日志，不要随意扩大绕过范围、关闭安全选项或重置已有规则。

## 反馈问题时提供什么？

- OpenWrt / KWrt 和 OpenClash 的版本。
- 是否开启路由器本机代理，使用规则模式还是全局模式。
- 插件页面显示的状态，以及出问题时的相关日志。
- 暂停代理后，校园网是否能正常访问。

请遮掉账号、密码、订阅链接和设备标识。我们需要根据实际环境判断原因，不建议套用其他人的整套配置。
