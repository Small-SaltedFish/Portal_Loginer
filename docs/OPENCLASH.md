# 同时使用 OpenClash

## 需要手动添加规则吗？

**1.4.1 起，通常不需要。** 填好校园账号并启动 Portal Loginer 即可，不必给探针添加 DIRECT 规则、填写 DSCP 或维护域名名单，也不用为此关闭 OpenClash 的路由器本机代理。

插件不会修改 OpenClash 的订阅、模板、分流规则或 DNS 设置。没有安装 OpenClash，或者 OpenClash 已停止时，插件正常直接联网。

## 它怎样避免被代理影响？

OpenClash 为自己发出的网络请求保留了绕过代理的机制。Portal Loginer 会先检查这项机制是否存在，再让检测和认证请求通过它直接发出。即使代理节点不可用，这些请求也不需要借用节点。

域名解析也单独处理：优先询问 WAN 提供的 DNS，失败时尝试阿里和腾讯公共 DNS，再用得到的真实 IP 访问原网址。这样既保留原网址和 HTTPS 校验，也避免探针拿到 Fake-IP 后再次进入代理。

这些普通 DNS 查询仅用于插件自己的探测和认证，不会接管手机、电脑的 DNS，也不代表整个局域网的 DNS 泄漏问题已经解决。校园认证必须能在尚未登录、代理不可用时工作，不能依赖先连上代理才能解析域名。

## 支持哪些情况？

支持带有进程组绕过规则的 OpenClash，包括采用 nftables（fw4）和 iptables（fw3）的实现。插件检查实际规则，不只看“本机代理”开关；能否绕过也不依赖规则模式或全局模式下的节点选择。

部分旧固件、改版 OpenClash、手工改过的防火墙可能没有这项机制。插件会提示无法建立独立请求，并保留现有校园登录，不会为了检测失败反复注销。其他代理插件、额外 VPN 和自定义策略路由不在这项自动适配的保证范围内。

如果需要反馈，请提供系统和 OpenClash 版本、插件页面状态与相关日志。不要先照搬别人的整套防火墙设置。

## 主探针设置还有用吗？

有。每轮先访问设置里的主探针，未得到明确结果时才尝试华为和 vivo 的备用地址。主探针应使用能正常返回 HTTP 204 的国内 HTTP 地址，不要填校园登录页或普通首页。更换主探针后，无需同步修改 OpenClash。

检测到当前校园认证页时，插件才自动登录；请求超时或普通网页跳转不会直接触发注销。

## 从 1.4.0 升级

新版不再读取旧的 `direct_tos` 选项，也不依赖此前为探针添加的 DSCP 规则和独立 DNS 名单。

升级不会自动删除你已有的 OpenClash 设置，避免误删兼用于其他业务的规则。只有以前照旧方案添加过配置的用户，才需要检查这些旧项目：

- 来源流量访问控制中，备注为 `PortalLogin_Direct_42` 的旧规则。
- `portal_login.main.direct_tos` 旧参数；新版已忽略它，删除不会影响功能。
- 仅为探针添加的第二 DNS、DNS 策略、Fake-IP 过滤和 DIRECT 例外。三个默认探针域名是 `connect.rom.miui.com`、`connectivitycheck.platform.hicloud.com`、`wifi.vivo.com.cn`。旧配置可能分散在覆写模块和自定义列表里，需要一起检查。

确认新版正常后，可以移除这些仅服务于 Portal Loginer 的项目，并应用 OpenClash 配置。订阅、GitHub 更新或其他设备仍在使用的 DNS 与直连配置应保留，不能把整个模块或 DNS 列表一并删除。
