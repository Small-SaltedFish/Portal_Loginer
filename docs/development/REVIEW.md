# 1.4.0 审查及验收记录

本文供维护者追踪开发过程，不是安装教程。

## 发布后复查

- 将 DSCP 标记、特定 OpenClash 防火墙链和第二 DNS 列表作为普遍前提不合理；只证明了一种现场配置可用。
- 默认未配置标记时，只因检测到本机代理开启便拒绝探测，会让普通安装受制于手动配套。这是待修复的兼容性问题，不应通过强迫用户改另一插件来掩盖。
- 主探针保存校验直接依赖另一插件的域名列表，使本插件设置与外部配置耦合，缺少通用的解析与出站方案。
- 自动把同一套特调写入所有设备并不能解决普适性，反而会覆盖用户的 DNS 或影响其他业务。未验证通用替代前，不新增自动改写 OpenClash 的行为。
- README 与 Release 改为面向使用者；移除重复 SHA256 发布附件。内部检查仍用于开发，但不作为普通用户的操作步骤。

基线：040e2a9；已阅读主程序、rpcd、LuCI、init、hotplug、配置、ACL、菜单、构建和两份说明文档。

## 必须满足的行为

- 无 WAN 地址、认证重定向、在线证据、探测不确定分别处理。
- 超时、HTTP 5xx 和普通重定向不得单独触发登出/重新认证。
- 不确定状态必须在界面展示，不得继续显示“已确认在线”。
- 登录响应、ack_auth 和随后联网验证分别检查。
- 守护循环和手动操作必须串行；服务重启不得隐含登出。
- OpenClash 的 Fake-IP、节点全失效、核心重启分别测试；`--noproxy` 不等于绕过透明代理。
- 升级保留账号、密码及自启动设置；不把现场凭据或日志提交到 GitHub。

## 基线发现

1. 超时分支无条件使用缓存重新认证；备用循环首轮结束后 break。
2. HTTP 错误和非认证重定向被判断为在线。
3. ack_auth 未检查，登录 API 成功即记录在线。
4. 前端重启先 restart 再 relogin，与 daemon 并发。
5. rpcd 手动命令没有认证互斥，状态读接口也会写状态。
6. 状态文件 sed 替换未转义 `&`、反斜杠；JSON 对控制字符和空数字处理不完整。
7. rpcd 配置缺少服务器端校验，配置临时文件包含密码但未限制权限。
8. 动态 WAN 设备发现依赖 UCI 静态 device/ifname，缺少 ubus 运行时结果。
9. CLI 参数在 load_cfg 后被覆盖；logs 的行数被选项循环消费。
10. ipk 缺少 conffiles；安装/升级和服务启用、重载行为需要回归验证。

## 候选迭代与证据（2026-11-04）

- rc1：设备构建时调用环境 umask077 导致部分共享程序目录被打包为 700。安装后 ubus 新连接失败，守护进程未启动。已停止验证、恢复目录为 755，管理接口和服务恢复；未采用重启路由器掩盖问题。
- rc2：固定构建 umask022、显式共享目录权限，加入包内容权限检查。修正固件 BusyBox 已提供 flock 而独立 flock 包依赖不可满足的问题。原版回退包也重新构建。
- rc3：页面显示版本和独立通道，说明一主两备、失败退避及参数范围；自定义主探针保存先验证独立 DNS，启用开关同步启动项；清除 WAN 不匹配的运行时门户参数，增加冷启动诊断。
- 待发布包已在目标设备的真实 ash、jsonfilter、jshn、UCI、flock 下通过 68 项隔离检查：core40、rpc16、locking4、daemon4、package4。包含系统校时、未安装/停用 OpenClash 的回归；隔离环境不提交真实认证请求，不修改真实 WAN/账号配置。
- Fake-IP 非 TUN，本机代理开启：规则、全局、直连模式的三个标记探针均为 204。先证明显式代理可用，再将 GLOBAL 指向 REJECT，显式代理失败而三个探针仍为 204；测试后恢复 rule。原生 OUTPUT 绕过计数增长。
- rc2 重启守护进程：配置、自启动、系统目录模式保持，未发生主动登出或重复认证。
- 用户手动校园注销：捕获真实 302，随后一次认证事务及联网验证成功；从发现认证跳转到成功约 2 秒，不含等待下一轮检查的时间。
- 路由器端 204 不作为普通 LAN 设备验收。另从电脑显式连接 KWrt 代理，国内 HTTP 与国外 HTTPS 测试地址均返回 204；此路径避免把手机热点直连算作 KWrt 恢复，但不能替代所有设备的透明转发和游戏测试。
- rc3 安装后状态、版本、登录时间和零失败计数正常。用户随后注销校园账号，将光猫与 KWrt 同时断电并一起通电：先无地址等待，取得 DHCP 后约 13 秒发现认证跳转，再约 3 秒成功；只发生一次认证，失败计数为 0，OpenClash 启动成功。
- 此轮同时发现 NTP 校时引起系统时间跳变。后续版本改用开机秒数计算稳定等待、限频和在线时长，日志保留开机秒数，不改写原始现场日志。待发布包仍须完成最终部署检查；持续稳定性和普通设备游戏不作为已实测项目。
- 按用户反馈删除多余“探测通道”显示。没有 OpenClash 时直接使用系统网络；检测到 OpenClash 时只在配置区显示共存提醒，并链接详细字段填写、验证和撤销文档。
- 最终 1.4.0 已部署到 KWrt，实际版本、运行状态和专用规则命中正常；真实页面确认不再显示“通道”，共存提醒及文档链接明显。通过页面提交未注册的自定义探针时，后端明确拒绝，真实主探针仍保持原值，随后表单复位。
- 用户选择不再安排第二次断网。最终 1.4.0 没有再次进行物理冷启动；此前 rc3 的真实冷启动证据与最终版的校时/无 OpenClash 回归分开记录，不能混写成同一版本的全部现场验证。
- 本次没有复现历史“上级发错 DHCP 租约”的失败现场，不能宣称该偶发问题的唯一根因已证实；也没有将所有 LAN 设备透明转发、国服游戏、TUN 模式或全网 DNS 抓包列为已验证。

原始诊断只保存在本地和路由器 root 私有目录，不进入公开仓库。本文不包含现场账号、密码、MAC、订阅或完整日志。

## 现场验收（由用户操作断网）

先验证非破坏性的 probe/status 与现有登录状态一致，再启用候选包。
每轮记录版本、时间、OpenClash 状态、探针结果、认证请求次数和恢复耗时。

1. 已在线：重启守护进程，不能发生登出或重复登录。
2. 用户在校园门户退出：观察 AC 返回（302、200 登录页、超时），确认一次认证恢复。
3. 外部探针单独失败：保持校园会话，不反复重认证。
4. OpenClash 节点不可用但国内网络正常：认证探针继续可用。
5. OpenClash 核心重启：不能因此触发校园登出。
6. WAN 断开、重新 DHCP：旧缓存参数不能覆盖新地址。
7. 错误密码/接口失败：显示失败、限速重试，不伪报在线。
8. 双击手动操作与定时重认证：最多一个认证事务。
9. 原版本升级、回滚：凭据和开机设置保留。

正式发布前须完成设备语法/隔离回归、升级保护、真实注销恢复和用户要求的冷启动验证；其他故障注入可用隔离用例覆盖，并明确记录现场未验证的边界，不能写成已全部实测。
